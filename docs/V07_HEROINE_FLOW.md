# v0.7 試作記録 — ヒロインの救出・仲間加入・ランダムイベント

日付：2026-11-09。対象：`index.html`、`tests/v07_heroine_flow.cjs`。

## ユーザーの改修要望

- 遠征10体目のヒロイン救出イベントはポップアップで目立たせる。
- 村長の娘は**最初の町・灰渡限定の仲間**として扱う。
- 出会い → 最初の交流 → 10体目救出 → 仲間加入という順番にする。
- 初回交流以降のヒロイン交流はメイドの提案から外し、戦闘後などのランダムイベントへ移す。
- メイドからの提案もランダム制にする。

## 実装

1. 初回の出会い（開始時）は従来どおり。メイドの提案に「村長の娘さんと初めてお話ししましょう！」が**初回交流が済むまで必ず出る**。これを選んだ後、遠征10体目での救出が発生する。交流前に10体突破しても救出しない。
2. 10体目で一度だけ救出し、`role=dialog` のポップアップを表示。ボタン「冒険を続ける」を押すまで戦闘シミュレーションは停止。救出の事実・娘の台詞・仲間加入を表示し、帰還結果と親密度履歴にも残す。
3. 救出時に `daughter.joined=true`、帰還後に町限定の編成候補へ追加。最大3人の既存編成規則を維持。枠に空きがあると次回遠征から自動参加、既に鍛冶見習いが出ている場合は町で待機し、プレイヤーが編成交代できる。娘は仮のHP20・攻撃3・初期遠距離攻撃、装備1枠とスプライトを持つ。
4. 救出後のヒロイン交流提案は廃止。帰還時38%（仮）の確率でお礼・偶然の遭遇・追加交流のいずれかが起き、親密度と履歴に記録。救出を行ったその遠征の帰還時は別の交流イベントを重ねない。
5. 提案候補から最大3つを毎回無作為抽選して表示。条件を満たさない候補は含めない。最初のヒロイン交流だけは必ず候補に残す。
6. v0.6から追加された鍛冶見習い、近遠距離戦闘、ランダム装備ドロップ、町育成、装備の付け替えは維持。住人個別のターン行動計算はない。

## データ構造

- `state.currentTown` は暫定的に `haiwatari` 固定。娘はこの町で `daughter.joined` が成立した時だけ仲間候補となる。**次のマップへの移動や保存・持ち越しそのものは未実装**。
- 親密度は0〜5、`firstExchange` と `joined` を追加。救出・お礼・偶然の遭遇はフラグと履歴で管理。
- 旧v0.5「救出前の町の選択に28%の交流抽選」「救出後の交流もメイド提案から選ぶ」という試作仕様はv0.7で置き換え。

## 検証

実ブラウザやTinyFishは使っていない。JavaScriptの構文チェックと、擬似DOM/V8環境の戦闘シミュレーションで以下を通過。

- 初回交流の必須表示、提案の毎回最大3件抽選と抽選差。
- 交流前の10体未救出、交流後の10体救出、ポップアップ表示。
- ポップアップの間は戦闘が進まず、ボタン後に再開する。
- 一度きりの救出、親密度上限、帰還後のランダム交流。
- 空き枠がある場合の娘の自動加入と戦闘、3人枠が埋まっている場合の待機と交代。
- 従来の町育成・戦利品・鍛冶見習いを妨げないこと。

再現用のNodeテスト：`node tests/v07_heroine_flow.cjs`（追加パッケージ不要）。
試作数値・抽選確率・人物の台詞・戦闘能力・3人枠は**正式仕様として決定していない**。iPhone実機のv0.7操作検証はまだない。
